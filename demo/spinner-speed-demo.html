spinner 转速曲线：随产量爬升，250 t/s 封顶

新机制：每 N 个 token 进一帧（转速 ∝ 吐字速率），达到封顶点后由时间闸门按住不再加快；完全静默时回退到 80ms 空闲节奏。左边现状、右边新方案吃同一条 token 流。

现状 · 每次重绘进一帧 ≥62 t/s 就一直顶满 62.5fps

token 一来就把重绘顶到 16ms 节流上限，spinner 跟着重绘走，与速率基本无关。

新方案 · 每 N token 进一帧 + 时间闸门 封顶点处恰好到达上限

⠋ Working… 0s
– 帧/秒 · – 圈/秒
012.5（设计）62.5（调度器上限）
机制与参数换算：
· 每帧消耗 N 个 token：转速 = t/s ÷ N，随产量线性爬升；同时有时间闸门（封顶转速 ms）兜底，两条线恰好相交于封顶点：封顶点 t/s = N × 1000 ÷ 封顶ms。默认封顶点 250、封顶 16ms → N = 4，即 250 = 4 × 1000/16（封顶 62.5 帧/秒）。
· 完全静默（连续 300ms 无 token，如思考中/工具运行中）时回退到 80ms 空闲节奏 = 12.5 帧/秒，与现状的空闲表现一致。
· 下方档位条：固定速率各跑一路，绿色 = 已达封顶（转速不再随速率变化）；灰色 = 随产量爬升区。「现状xx」为该速率下现状的分析值对照。
· 落地改法：流式 delta 处累加 token 计数（如 drain_agent_events），三处进帧点（editor.rs:1588、status_indicator.rs、loader.rs）改为「计数 ≥ N 或静默回退，且距上次进帧 ≥ 封顶ms」才进帧；editor.rs:1751 起的 spinner 测试同步改语义。
